# TracerViewer 轨迹分析工具

## 简介

TracerViewer 是一款用于浏览和分析 AI 编程助手执行轨迹的可视化工具，支持同时查看来自 **Claude Code**、**Codex** 和 **Kimi Code** 的对话会话记录。通过统一的数据模型，你可以清晰地看到每一次人机交互的完整过程：用户指令、模型思考、工具调用、执行结果以及最终回复。

---

## 快速开始

### 环境要求

- Node.js 18+
- 本地存在至少一个 AI 工具的会话记录（见下方数据来源）

### 方式一：双击 .command 文件（macOS 推荐）

在 Finder 中找到项目根目录下的 **`Trace Viewer.command`**，双击即可启动。

它会自动完成以下步骤：
1. 检测 `node_modules` 是否存在，若缺失则先执行 `npm install`
2. 启动后端 API（端口 3001）和前端开发服务器（端口 5173）
3. 等待服务就绪后，自动在默认浏览器中打开 `http://localhost:5173`

> **首次使用**：macOS 可能提示"无法验证开发者"，需在「系统设置 → 隐私与安全性」中点击「仍要打开」，或在文件上右键 → 打开。

### 方式二：命令行启动

```bash
# 进入项目目录
cd trace-viewer2

# 首次使用需先安装依赖（或使用 npm run setup 检查环境）
npm install

# 启动（后端 API 端口 3001 + 前端开发服务器端口 5173）
npm run dev
```

启动后在浏览器访问：`http://localhost:5173`

### 构建生产版本

```bash
npm run build
```

## 数据来源

工具会自动扫描以下本地目录，无需任何手动配置：

| AI 工具      | 会话文件路径                          | 格式   |
|-------------|--------------------------------------|--------|
| Claude Code | `~/.claude/projects/**/*.jsonl`       | JSONL  |
| Codex       | `~/.codex/sessions/**/*.jsonl`        | JSONL  |
| Kimi Code   | `~/.kimi-code/sessions/**/state.json` + `agents/main/wire.jsonl` | JSON + JSONL |

> 工具启动时会自动遍历上述目录，解析会话文件并统一转换为内部数据格式。

## 左栏：会话列表

### 搜索

在顶部搜索框中输入关键词，可实时过滤会话，支持按以下字段匹配：

- 项目路径（工作目录）
- 会话 ID

点击搜索框右侧的 `×` 按钮可清空搜索词。

### 时间过滤

搜索框下方第一组按钮用于限制加载范围：

| 按钮 | 作用 |
|------|------|
| 1d | 只加载 1 天内的会话（默认） |
| 7d | 加载 7 天内的会话 |
| 30d | 加载 30 天内的会话 |
| Other | 加载 30 天以前的会话 |

该过滤会传递到后端扫描逻辑中，用于减少初始文件扫描和解析量。

### 来源过滤

时间过滤下方是来源过滤按钮：

| 按钮 | 作用 |
|------|------|
| All  | 显示所有来源的会话（默认） |
| Claude Code 图标 | 只显示 Claude Code 会话 |
| Codex 图标 | 只显示 Codex 会话 |
| Kimi Code 图标 | 只显示 Kimi Code 会话 |

按钮上的数字为对应来源的会话总数。再次点击已激活的来源按钮可取消过滤，回到 All 视图。

### 会话条目

每条会话显示：

- **来源图标**：标识该会话来自哪个 AI 工具
- **项目路径**：会话的工作目录（过长时自动截断，显示末两级路径）
- **时间**：距离会话开始的相对时间（如 `5m`、`3h`、`2d`）
- **短 ID**：会话 ID 的前 8 位
- **Turn 数量**：该会话包含的对话轮数
- **模型名称**：使用的模型（如有）

点击任意会话条目，右栏将加载并展示该会话的完整轨迹。

### 主题切换

左栏底部有一个图标按钮，点击可在**亮色模式**和**暗色模式**之间切换，偏好设置会保存到本地存储。

## 右栏：轨迹详情

### 会话头部

选中会话后，右栏顶部显示该会话的概要信息：

- **来源标签**：Claude Code / Codex / Kimi Code（带对应颜色）
- **模型标识**：所使用的模型名称
- **会话 ID**：完整 ID，可选中复制
- **工作目录**：项目根路径
- **时间戳**：会话开始时间
- **统计数据**：对话轮数和工具调用总次数

### Turn（对话轮次）

每个 Turn 代表一次完整的「用户输入 → 模型响应」循环，以数字标号显示在左侧。

#### 用户消息

显示在右侧（右对齐气泡），渲染 Markdown 格式。

#### 助手响应区

包含以下部分：

**Token 用量统计**（若有）：

| 标签 | 含义 |
|------|------|
| `↑ N` | 输入 Token 数 |
| `↓ N` | 输出 Token 数 |
| `⚡ N` | 缓存命中 Token 数（金色高亮） |

**步骤区（Steps）**：

点击步骤区标题按钮可以展开/折叠当前 Turn 的所有中间步骤，按钮上显示步骤数量（如 `3 tool calls` 或 `5 events`）。

**最终回复气泡**：助手的文字回复，渲染 Markdown 格式。

## 步骤类型说明

步骤（Step）是模型在响应过程中产生的每一个原子事件，共有以下五种类型：

### 工具调用对（Tool Call + Result）

工具调用及其执行结果会配对展示在同一个卡片中：

- **卡片头部**：显示工具名称（如 `Bash`、`Read`、`Edit`）以及参数预览
- **状态徽章**：`SUCCESS`（绿色）/ `FAILED`（红色）/ `PENDING`（灰色）
- **展开后**：
  - **Arguments**：JSON 格式的调用参数，超过 5000 字符时截断
  - **Response Output / Error Trace**：工具返回的内容，超过 800 字符时折叠，点击底部按钮可展开完整内容

常见工具预览格式：

| 工具类型 | 预览内容 |
|---------|---------|
| Bash    | 命令字符串（前 80 字符） |
| Read/Write/Edit/Glob | 文件路径或 glob 模式 |
| Grep    | 正则表达式 `/pattern/` |
| 其他    | 第一个字符串参数值 |

### 思考过程（Thinking）

模型的内部推理内容，以虚线边框、金色主题展示，默认折叠。展开后可查看完整思考链。折叠时显示前 80 字符的预览。

### 文字消息（Text）

助手在步骤序列中间产生的文字块，以助手气泡样式渲染 Markdown。

### 系统日志（System Log）

系统级事件或任务状态记录（如任务开始/完成/失败），可展开查看原始内容。

不同来源以独特颜色标识，便于快速区分：

| 来源 | 颜色 | 说明 |

| Claude Code | 橙色 | `#c2410c` |

## 内部数据模型

所有来源的数据均被统一解析为如下层级结构：

```
TraceSession
 ├── id, source, startedAt, cwd, model
 └── turns: TraceTurn[]
      ├── id
      ├── userMessage
      ├── assistantMessage
      ├── tokenUsage (input / output / cached / total)
      └── steps: TraceStep[]
           ├── type: 'tool_use' | 'tool_result' | 'thinking' | 'text' | 'system'
           ├── name (工具名)
           ├── input (工具参数, JSON 对象)
           ├── output (工具返回内容)
           ├── text (文字内容)
           └── isError (是否为错误)
```

## 常见问题

**Q：左栏显示 "No sessions found"，该怎么办？**

检查以下路径是否存在对应的会话文件：

- `~/.claude/projects/` — Claude Code
- `~/.codex/sessions/` — Codex
- `~/.kimi-code/sessions/` — Kimi Code

确保 AI 工具已运行过至少一次并产生了会话记录。

**Q：某个会话无法加载，显示 "Parsing Error"？**

该会话文件可能格式异常或不完整（如写入中断）。可尝试直接查看原始文件确认格式是否正确。

**Q：工具调用的参数内容显示为截断？**

超过 5000 字符的 JSON 参数会被截断以保证性能。如需查看完整内容，可在后端日志中查找原始文件。

**Q：如何仅查看某一类 AI 工具的会话？**

点击左栏顶部对应来源的图标过滤按钮即可。
